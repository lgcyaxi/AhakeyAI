# Recommendation-led clarification

Guide version 1.1 -- private-source publication boundary

Open this guide only when repository inspection cannot resolve a consequential
choice in the request.

Jump to: [trigger](#trigger) · [one-question turn](#one-question-turn) ·
[convergence](#convergence) · [authority boundary](#authority-boundary)

## Trigger

Inspect the repository and safe read-only evidence first. Ask when the
remaining uncertainty could materially change the outcome, audience,
acceptance evidence, write boundary, compatibility, protected data, or risk.
Do not interview a clear mechanical task or ask for facts the repository can
answer.

## One-question turn

Ask the single unresolved question with the highest downstream impact. State:

```text
Current read: <working interpretation>
Question: <one decision>
Recommended: <proposed answer>
Why: <evidence, benefit, and main trade-off>
```

Wait for the answer before asking another consequential question.

## Convergence

After each answer, update the interpretation, remove questions that became
irrelevant, and continue only if another answer would still change the result.
When the maintainer says "you decide", take the recommendation as an explicit
assumption and proceed within existing authority.

## Authority boundary

A recommendation or delegated design choice does not authorize a push,
publication, deployment, destructive operation, history rewrite, expensive
run, credential use, or external message. Obtain the explicit authorization
required for that action.
